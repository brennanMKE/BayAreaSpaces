## Description

Push the finished, validated event set to the Postgres database on AWS EC2 that the website project reads. This is the handoff boundary between the two projects: this repo writes, the website reads.

## Expected behavior

- Runs only after health gates pass (issue 0016).
- Connection details from `$MAKER_CALENDAR_PG_DSN` or whatever issue 0003 settles on — never committed.
- Upsert semantics per issue 0003.
- Idempotent: re-running the same night's data changes nothing.

## Actual behavior

Blocked on issue 0003. Until then the pipeline emits to `out/` and that is the interface.

## Notes

Do not start this before 0003 is answered — connection method, schema ownership, and replace-vs-upsert all change the implementation, and getting it wrong bakes a bad assumption into the seam between two repos.

Supersedes the handoff's Part 4 proposal of committing `out/` to GitHub Pages.

Whatever the answer, UID stability is what makes this safe. If the table is replaced per run, a UID change is invisible here but very visible to subscribers; if it merges on `uid`, a UID change silently duplicates every event.
