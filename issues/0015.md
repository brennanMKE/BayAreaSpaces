# 0015 — Dedupe across sources and spaces

| | |
|---|---|
| **Status** | open |
| **Module** | dedupe |
| **Platform** | macOS |
| **First seen** | 2026-08-05 |

## Description

Several spaces publish the same event through more than one source, deliberately. Ace has REST + ICS + JSON-LD; Maker Nexus has a gCal and a JSON cache; The Crucible has a catalog blob and a WooCommerce API that cross-validate at 271 vs 274 events.

## Expected behavior

**Within a space:** collision when `space_id` matches, starts are within 30 minutes, and `rapidfuzz.token_set_ratio(a, b) >= 85`. Keep the higher-`trust` record; merge in non-null fields the winner lacks. Log every merge so the threshold can be tuned.

**Across spaces:** drop the `space_id` match but require similarity `>= 92` **plus** an address match. Real cases exist — Sudo Room's Luma feed carries events at The Box Shop, and a group posting to both Frontier's Luma and its own page.

**Field-level merge preferences already known:** Maker Nexus's JSON cache wins on price and capacity while the gCal wins on coverage; The Crucible's WooCommerce API wins on description and price while the blob wins on category (its own categories are polluted with 60+ one-off per-product entries equal to the class title).

## Notes

Ace's `tribe_rest` and `tribe-ics-list` are byte-equivalent in content — the registry already notes not to ingest both as separate sources, but dedupe is the backstop if someone enables both.

Do not dedupe on title alone. Maker Nexus has 76 distinct equipment-training titles repeating across 171 instances; they are genuinely different events at different times.
