## Description

Several spaces publish the same event through more than one source, deliberately. Ace has REST + ICS + JSON-LD; Maker Nexus has a gCal and a JSON cache; The Crucible has a catalog blob and a WooCommerce API that cross-validate at 271 vs 274 events.

## Expected behavior

**Within a space:** collision when `space_id` matches, starts are within 30 minutes, and `rapidfuzz.token_set_ratio(a, b) >= 85`. Keep the higher-`trust` record; merge in non-null fields the winner lacks. Log every merge so the threshold can be tuned.

**Across spaces:** drop the `space_id` match but require similarity `>= 92` **plus** an address match. Real cases exist — Sudo Room's Luma feed carries events at The Box Shop, and a group posting to both Frontier's Luma and its own page.

**Field-level merge preferences already known:** Maker Nexus's JSON cache wins on price and capacity while the gCal wins on coverage; The Crucible's WooCommerce API wins on description and price while the blob wins on category (its own categories are polluted with 60+ one-off per-product entries equal to the class title).

## Notes

Ace's `tribe_rest` and `tribe-ics-list` are byte-equivalent in content — the registry already notes not to ingest both as separate sources, but dedupe is the backstop if someone enables both.

Do not dedupe on title alone. Maker Nexus has 76 distinct equipment-training titles repeating across 171 instances; they are genuinely different events at different times.

## Root cause

Not a bug — a stage that had never been written. `pipeline/dedupe.py` was a docstring scaffolded by issue 0004, and `run_pipeline` set `dedupe_skipped_reason = "dedupe is not implemented yet (issue 0015)"` and passed every event through unmerged. Issue 0012's `collapse_uid_collisions()` was standing in for it and could only see *exact* UID equality, which is the one case where two sources happen to agree on an identifier. Ace's REST and ICS feeds, Maker Nexus's gCal and cache, and The Crucible's blob and API all namespace their UIDs differently by construction, so none of their duplicates were visible to it at all.

## Fix

New `pipeline/dedupe.py`, wired into `run_pipeline` ahead of the UID floor.

**Two passes, in order.** Within a space at 85, then across spaces at 92 plus an address match, over the survivors of the first. Doing the cross-space pass second means each space's internal duplicates are already one record, so a cross-space comparison sees the best copy each space has rather than an arbitrary one.

**The 30-minute window is the safety, not the title.** Maker Nexus has 76 distinct equipment-training titles across 171 instances and two of them score 100 against each other. The window is checked before `token_set_ratio` is ever called, so the false-positive regression is structurally impossible rather than merely unlikely — and the regression test asserts `comparisons == 0` for a pair 45 minutes apart, which would fail if that order were ever reversed.

**Cross-space needs both halves.** Similarity alone across spaces is how one space's calendar ends up published under another's name; `DedupePolicy` can turn cross-space merging off wholesale but deliberately offers no knob to keep it while dropping the address requirement. `address_similarity` folds street-suffix spellings (`Avenue`/`Ave`), treats a leading house number as decisive (951 and 953 Hudson Ave share a street, a city and a ZIP), and refuses anything under two tokens so a bare city name cannot match every event in it.

**Winner selection.** `trust` from `sources.yaml` via `trust_map(registry)`, then an on-site record over an `off_site` one, then field count, then the UID. The last two exist so the result is identical on every run: a merge that flipped nightly would churn subscribers just as badly as a UID change.

**What the winner keeps.** Its own UID — asserted in `merge_pair`, because every merge would otherwise re-notify every subscriber every night. The earlier `first_seen` of the two, because RSS `pubDate` reads it (issue 0018) and a merge is not a new event. `content_hash` is recomputed only when a merge changed a field the hash covers; the recomputation is deterministic, and issue 0014's store keys "did this event change?" on exactly that value.

**Field preferences are data.** `DEFAULT_FIELD_PREFERENCES` names Maker Nexus's cache for `price` and The Crucible's API for `description`/`price` with the blob keeping `categories`. A preference redirects where a field is *sourced from* and never erases — and, critically, a non-preferred source may not fill the field even when the preferred one is empty. That last clause is the whole point of the Crucible rule: a blob entry with no `department` must not quietly acquire a category named after itself. A preference naming a field `Event` does not carry raises `DedupeError` at construction; Maker Nexus's documented capacity preference is therefore **not** expressible today and is recorded in the module docstring instead of being silently inert.

**Complexity.** Both passes sort by start and slide the window, so fuzzy comparison only sees time-plausible pairs — 3000 events cost about 6000 comparisons rather than 4.5 million. Candidate pairs become clusters via union-find, and each cluster is reduced against its own winner, so a chain (A~B, B~C, A≁C) cannot drag an event 58 minutes away into a merge.

**The merge log.** `DedupeResult.merges` carries both UIDs, both source labels, both trust values, the score, the start delta, the address score and the fields that moved; `summary()` is JSON-ready for `health.json` (issue 0017). `NearMiss` records time-plausible pairs that scored within 10 of the bar, or that cleared the score and failed the address — the other half of "log every merge so the threshold can be tuned", capped at 500 with the full count retained.

**`collapse_uid_collisions` is kept, not replaced.** Two events can share a UID and start hours apart under different names — a source reusing one `UID` for two occurrences without an `RRULE` does exactly that — and no start-plus-title rule will ever pair them, while `emit_ics` still refuses that calendar fatally for every space at once. Dedupe is judgement; that is a floor, and the floor is still wanted. Its log line now says so.

## Gotchas

**The test fixtures had to start varying the event title per feed.** Both `tests/test_cli.py` and `tests/test_carry_forward.py` served one identical calendar body to every source, differing only in the UID. That is thirteen sources publishing one identically-named event at one address, which dedupe correctly collapses to a single record — and seven unrelated tests started failing on their event counts. The fixtures now derive the `SUMMARY` from the feed URL as well as the `UID`. Anyone adding a fixture feed should do the same, or be deliberate about wanting a merge.

**A merge changes which space owns the event.** A cross-space merge publishes the loser's event under the winner's `space_id` and `source_label`. That is the intent — The Box Shop's own calendar should own the Hudson Ave event that Sudo Room's Luma also carries — but it means a space's event count can drop for a reason that is not a source failure. Issue 0016's gates read per-source counts from before dedupe, so they are unaffected; anything later that counts per space is not.

**Clustering is transitive and the pair test is not.** A~B and B~C put all three in one cluster even when A≁C. `_reduce` re-tests every member against the winner it would fold into, and what does not match forms its own group. Removing that re-test would silently widen the 30-minute window to the length of a chain.

**`trust_map` is keyed on `(space_id, source_label)` where the label is the registry `label` or the adapter name.** Same rule as `pipeline.fetch.source_label`, and it must stay that way: an event carries the label, not the source object, and a lookup miss silently means trust 0 — which does not error, it just makes an arbitrary record win.

**Capacity is not a mergeable field.** Maker Nexus's JSON cache should win it, the research says so, and `Event` has no capacity field. Declaring the preference anyway raises `DedupeError` by design. When capacity is added, add it to `MERGEABLE_FIELDS` *and* to `DEFAULT_FIELD_PREFERENCES`.
