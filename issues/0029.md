## Description

The second and larger of the model's two jobs: assign category tags and write a one-line summary for the RSS feed. Genuinely a language task, unlike parsing.

## Expected behavior

- Tag each event: woodworking / electronics / textiles / metal / fabrication / social / class-vs-open-shop, seeded from `references/categories.json`.
- Write a one-line `summary_line` for RSS.
- Strict JSON schema, Pydantic-validated, `temperature=0`.
- **Never let LLM output into a UID.** Categories and summaries are display fields only.
- Cache by `content_hash` so unchanged events are not re-tagged nightly — this is the highest-volume model call in the pipeline and most events persist for weeks.

## Notes

`references/categories.json` seeds the taxonomy with per-interest keywords (Electronics → Soldering, Circuits; Fabrication → 3D Printer, Laser Cutter). Expand it as real event titles arrive rather than guessing up front.

Useful signal already in the data: several sources carry their own categories worth mapping rather than inferring — Ace's TEC categories (10 slugs), The Crucible's `department` field, Maker Nexus's `CategoryName`. Prefer the source's own taxonomy where it exists and reserve the model for sources with none.

Strip HTML before tagging: Maker Nexus's `DESCRIPTION` is HTML with instructor, ages, capacity and a signup link.
