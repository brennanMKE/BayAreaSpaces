## Description

Produce the merged calendar — the artifact that makes every later decision easier to judge, and the demo that makes outreach persuasive.

## Expected behavior

- One `VCALENDAR`, `PRODID:-//brennan.sstools.co//maker-calendar//EN`, `X-WR-CALNAME:Bay Area Makerspaces`, `X-WR-TIMEZONE:America/Los_Angeles`.
- **Emit expanded instances, not RRULEs.** Cross-client recurrence handling is where this goes wrong, and expansion is already in memory.
- Every `VEVENT` carries `URL` pointing at the space's own page and `ORGANIZER` naming the space. The point is to drive people to the spaces.
- Prefix `SUMMARY` with the space: `[Ace] Sewing 101 Bootcamp`.
- `DESCRIPTION` truncated to roughly 300 characters plus a link — sidesteps the copyright question and reads better merged.
- Also emit per-space files under `out/spaces/{space_id}.ics`.
- **Validate before replacing the live file**: round-trip through `icalendar`, assert it parses and the event count is within tolerance.

## Actual behavior

Nothing emitted.

## Notes

This is the Phase 1 deliverable. With issues 0004–0010 done, `ics` and `gcal_ics` alone cover Ace, Sudo Room, Noisebridge, Frontier, Humanmade, The Box Shop, Hacker Dojo, Maker Nexus and Sequoia Fabrica's member calendar — most of the actual event volume, with no LLM, no browser, no dedupe and no database.

## Root cause

`pipeline/emit_ics.py` was a docstring-only stub from the issue 0004 scaffold. Everything upstream — fetch, the two ICS adapters, normalize, filters — produced canonical `Event` records that nothing turned into an artifact, so there was no way to look at what the pipeline actually collects and no demo to show a space when asking for a feed.

## Fix

`pipeline/emit_ics.py`, in four layers:

**Build.** `build_vevent` / `build_calendar` render `Event` records into `icalendar` components. One `VCALENDAR` with `PRODID:-//brennan.sstools.co//maker-calendar//EN`, `X-WR-CALNAME:Bay Area Makerspaces`, `X-WR-TIMEZONE:America/Los_Angeles`. Every `VEVENT` carries `UID` (verbatim — it is the subscriber-stability contract), `DTSTAMP` (the run timestamp), `SUMMARY` prefixed with the space, a `DESCRIPTION`, `LOCATION` when known, `ORGANIZER` naming the space and pointing at its own page, `URL`, and `X-MAKER-SPACE-ID` / `X-MAKER-SOURCE` provenance for issue 0017.

**Shapes.** All-day events are written from issue 0009's local, inclusive `start_date` / `end_date` as `DTSTART;VALUE=DATE` with RFC 5545's *exclusive* `DTEND` (last day + 1). Timed events are written from `start_utc` / `end_utc` as bare-`Z` instants. `RRULE` is never emitted, even when `Event.rrule` and `Event.recurring` are set: the adapter has already expanded the series against the horizon, and re-stating the rule would duplicate it in every client that honors it.

**Validate.** `validate_ics` round-trips the bytes back through `icalendar` and asserts it parses, is a `VCALENDAR` with `PRODID`/`VERSION`, has an event count within tolerance, carries `UID`/`DTSTAMP`/`DTSTART`/`SUMMARY`/`URL`/`ORGANIZER` on every `VEVENT`, carries no `RRULE`/`RDATE`/`EXRULE`, has unique non-empty UIDs, has no naive `DTSTART`, and gives every all-day event a real `VALUE=DATE` start with an exclusive end. It returns a `Validation` record rather than only raising, so the counts are reportable.

**Publish.** `emit_ics` renders **and validates every file** — merged plus each per-space calendar — before writing any of them, then writes each through `write_atomic`: a temp file in the destination directory, `fsync`, `os.replace`. A failure anywhere leaves the whole of `out/` exactly as it was, with no temp file behind. Quarantined events are refused at the door and counted in `EmitResult.skipped_quarantined` rather than disappearing; an event naming a `space_id` the registry does not have raises `UnknownSpaceError` rather than being published unattributed.

Public API for the issues downstream: `emit_ics(events, *, spaces, out_dir=OUT_DIR, dtstamp=None, tolerance=0, per_space=True, prefer_event_url=True, description_limit=300, name=CALNAME, timezone=CALTIMEZONE) -> EmitResult` (0012's CLI), `EmitResult.summary()` (0017's `health.json`), and the seams 0018 mirrors for RSS: `emit_string`, `build_calendar`, `render`, `validate_ics`, `write_atomic`, `truncate`, `build_summary`, `build_description`, `publishable`, `sort_events`, `space_index`.

## Gotchas

- **`icalendar` round-trips text through `vText`, and `repr()` lies about it.** `repr(vevent.get("SUMMARY"))` shows `vText(b'[Ace\\, Inc] …')` — the *escaped* wire form — while `str(...)` gives the decoded `[Ace, Inc] …`. A test that compared `repr` or the raw property would have "proved" that escaping round-trips wrong. Compare with `str()` or `.decoded()`.
- **Do not pre-escape anything.** `icalendar` escapes `,`, `;`, `\` and newlines on the way out and folds at 75 octets. Escaping first double-escapes every backslash and it does not show up until a client renders it.
- **`ORGANIZER` takes a `CAL-ADDRESS`, and `icalendar` quotes the `CN` for you.** `ORGANIZER;CN="Ace Makerspace, Inc":https://acemakerspace.org/` — the comma in a space name forces the quoting, which is exactly why a comma-bearing space name is in the test fixtures.
- **All-day must be written from the dates, not the instants.** `start_utc` for an all-day event is midnight *Pacific*, i.e. `07:00Z`/`08:00Z`. Rendering the instant would show the event at 7am and put it on the previous day for anyone east of here. `test_all_day_uses_the_local_dates_not_the_utc_instants` asserts `20260904T070000Z` never appears.
- **`DTEND` for `VALUE=DATE` is exclusive.** The record's `end_date` is the inclusive last day, so emit adds one day. A three-day festival that comes back as two days is the failure mode, and it looks plausible.
- **Validate everything before writing anything.** The first draft wrote the merged file, then rendered the per-space ones. A per-space failure would then have left a fresh merged calendar beside stale per-space files — internally inconsistent, and worse than either file being stale.
- **`DTSTAMP` changes every night by design**; `UID` does not. They are different contracts, and only the second one churns subscribers.
- **`Calendar.from_ical` raises `ValueError` for a truncated file** (`"Found no components where exactly one is required"`) rather than returning a partial calendar — which is what makes the round-trip gate cheap. It does *not* object to a `VEVENT` with no `UID`, so those checks are ours.
- **`icalendar.Event` collides with `pipeline.normalize.Event`.** Imported as `VEvent` here; anything importing both needs to do the same.
- Stale per-space files are not pruned: a space that stops producing events keeps its last `out/spaces/{id}.ics` until something removes it. Left for the publish step (0016/0017), which is where "what should be live" is decided.
