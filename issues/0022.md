## Description

Fetch a standalone JSON document and map a bespoke shape onto the canonical schema. Two consumers with quite different shapes.

## Expected behavior

**Maker Nexus — undocumented public cache.** `storage.googleapis.com/makernexus_amilia_activities_cache/events.json`. Dict keyed `YYYY-MM-DD_<amiliaId>`; **use the key as the UID**. Fields: `Name`, `Description`, `Url`, `CategoryName`, `Price`, `SpotsRemaining`, `StartDate`/`EndDate` as ISO-8601 with `-07:00`. 30 forward-looking events, `Last-Modified` same day. Richer than their ICS for the same events, so it wins the dedupe merge on price and capacity.

**The Crucible — WooCommerce Store API.** `wp-json/wc/store/v1/products` with `per_page=100` and **`orderby=date`**.

- **`orderby=date` is load-bearing.** Without it the endpoint returns HTTP 200 and valid JSON with `X-WP-Total: 98` instead of 353 — 72% of the catalog silently missing, covering only 40 of 216 live courses. Nothing about the response looks wrong. Assert the total.
- Paginate on `X-WP-TotalPages`. `page=99` returns 200 with `[]`, not an error, so **never paginate until-error**.
- Dates live in `attributes[].terms[].name` as `MM/DD/YY H:MM am/pm` local.
- **Drop the literal sentinel `01/01/70 12:00 am`** — naive `%y` parsing maps it to 2070 and it sails past every horizon check.
- Do not filter on its categories: 60+ one-off per-product categories equal the class title. Use the blob's `department` (issue 0021).

## Notes

The `orderby=date` trap is the most dangerous shape found in the whole survey — correct-looking and quietly amputated. It was caught only because two independent sources disagreed on the count.

Maker Nexus's GCS bucket cannot be enumerated anonymously (401 on `storage.objects.list`). `activities.json` and `camps.json` were found by name-guessing and are stale and dateless; there may be a classes cache worth asking staff about.

## Root cause

Not a defect — the tenth adapter, and the last of the four Tier A JSON shapes. Two registered sources named `adapter: json` and the dispatch table had no entry for it, so both were skipped with this issue number on every run: The Crucible's WooCommerce Store API (`trust: 90`, 274 offerings inside the horizon, the independent cross-validation of the `embedded_json` blob's 271) and Maker Nexus's Amilia community-events cache (`trust: 90`, 30 forward-looking events, the only source carrying their prices and seat counts).

The design problem worth naming is that the two documents have **nothing in common** — one is a dict keyed by identifier with ISO-8601 offsets, the other a paginated list of WooCommerce products whose dates hide inside `attributes[].terms[].name`. A single hardcoded field map cannot serve both, and sniffing which one arrived would be a guess of exactly the kind CLAUDE.md forbids.

## Fix

`pipeline/adapters/json_doc.py`. **The module is `json_doc.py`, not `json.py`**: under Python 3's absolute imports a module named `json` inside `pipeline/adapters/` is not what `import json` resolves to, but it is what every reader will assume it is, and `from pipeline.adapters import json` would shadow the stdlib name at any call site that also needs the real one. `sources.yaml` still names the adapter `json`; only the file differs, and `pipeline/adapters/__init__.py` says why.

**Reuse, not duplication.** Issue 0021's `FieldMap`, `resolve_path`, `parse_iso`, `parse_epoch` and the `_clean`/`_money`/`_strings`/`_bool` helpers are imported. `JsonFieldMap` subclasses `FieldMap` and adds `keyed`, `end`, `start_container`, `terms_taxonomy`, `term_uid`, `price_kind`, `spots_remaining`, `max_attendance` and `html_fields`, and widens `categories`/`price` to allow `None`.

**The registry names the shape.** A new `Source.shape` field, required for `adapter: json` and validated against `SHAPES` at load time — the same contract `script_id` has for `embedded_json`. Two shapes are registered: `amilia_activities_cache` and `woocommerce_store_products`.

**Maker Nexus.** `keyed=True`, so the document must be a dict of objects and the key is used verbatim as the UID; `normalize.py` namespaces it to `maker-nexus:2026-08-06_2314915`. `StartDate`/`EndDate` parse through `parse_iso` and the `-07:00` offset is kept exactly as written, with the literal offset preserved on `source_tz` and a **resolvable IANA name** on `tz`, because `normalize.day_start_utc` and issue 0016's health filter both call `ZoneInfo` on it outside the per-source `try`. `Price` maps to `price` (source text, never a float); `SpotsRemaining`/`MaxAttendance` ride on the event for diagnostics.

**The Crucible.** `start_container="woo_terms"` walks `attributes[]` for the `pa_class-date` taxonomy and yields each `terms[].name`, parsed as `MM/DD/YY H:MM am/pm` with an explicit `strptime` format. UID is `{product_id}:{term_id}` — both WordPress ids, stable by construction, and deliberately *not* the blob's `{id}:{start_epoch}`, so the two Crucible sources meet in dedupe on title and start rather than being silently identical. `prices` is rendered from minor units as source text, with `price_range` becoming `"$95 - $125"`. Descriptions are tag-stripped. `categories` is `None` for this shape, so the polluted per-product categories never reach `Event.categories` where issue 0010's filters run; they are kept on `source_categories` as diagnostics.

**The amputation is detected twice, by independent means.** `JsonShape.required_params` checks `orderby=date` on the URL that actually went out, before the body is read; and a new `Source.min_total` (300, against the observed 353) is compared against `X-WP-Total` off the response. Neither check trusts the other: the first catches our mistake at the moment it is made, the second catches a server that changes its mind while the parameter is still present. A declared floor with **no** total header is its own failure — losing the guard is losing the source.

**Pagination is `X-WP-TotalPages`, never until-error**, with pages 2..n requested as the same query string plus `page=N` so `orderby=date` survives to page 4. An empty list arriving before the declared last page stops the walk and is reported as a note. A failed later page fails the whole parse, so carry-forward republishes last night's complete catalog.

`JsonEvent` subclasses `IcsEvent` and `JsonParse` subclasses `IcsParse`, so `normalize_ics`, the CLI's `SourceRecord` and issue 0016's gates consume this adapter unchanged. `AdapterEntry("json", "0022", parse_json, paginates=True)` hands it the fetcher and the `SourceRef`, which is exactly the two things it needs.

## Gotchas

- **`orderby=date` failing loudly is the whole point, and it will look like a false alarm one day.** If The Crucible's catalog ever legitimately shrinks below 300 products, the run will block on `TRUNCATED_CATALOG` and someone will be tempted to lower `min_total` to make it green. Check `product-sitemap.xml` first: it agreed with `X-WP-Total: 353` (354 URLs) on 2026-08-05, and it is the independent second opinion.
- **The sentinel is dropped as text, before parsing.** Relying on a horizon check to catch it does not work: `dateutil` reads `70` against a window centred on the current year, so `01/01/70 12:00 am` becomes **2070** — inside no horizon and outside no sanity window. `strptime`'s `%y` reads the same string as **1970**, which is out of horizon and therefore harmless, so which parser you reach for silently decides whether this bug exists. This adapter uses `strptime` with an explicit format *and* drops the string *and* range-checks the year, which is three nets for one sentinel, on purpose.
- **`min_total` is registry data, not an adapter constant.** Maker Nexus deliberately has none: its cache carries 30 events and no total header, and inventing a floor for it would be a number nobody measured.
- **Do not "fix" `categories=None` on the WooCommerce shape.** It looks like a missing field map entry. It is the finding: 60+ of the 118 distinct category names are one-off per-product categories equal to the class title, so publishing them would give issue 0010's `categories_exclude` nothing usable to match and would let this source fill a field dedupe has already assigned to the blob's `department`.
- **The two Crucible sources must not share a UID form.** The blob uses `{id}:{start_epoch}` and this adapter uses `{id}:{term_id}` even though both `id`s are the same WordPress post. Making them identical would collapse the pair in `collapse_uid_collisions` instead of merging them in dedupe, and the field preferences (WooCommerce wins `description`/`price`, blob wins `categories`) would never run.
- **The GCS bucket cannot be enumerated.** `storage.objects.list` returns 401 anonymously, so `events.json` was reached by name. `activities.json` and `camps.json` exist and are **stale and dateless** — course-catalog templates keyed by course name with a `NextClassDate` and no `StartDate` field at all, `Last-Modified` 2025-12-19 and 2025-07-25. Neither is registered and neither should be. Already probed and 404'd: `classes.json`, `class.json`, `sessions.json`, `calendar.json`, `activities_cache.json`, `all.json`, `index.json`, `youth.json`. If a classes cache exists, ask staff for the object name rather than guessing again.
- **Capacity has nowhere to go yet.** `SpotsRemaining`/`MaxAttendance` are on `JsonEvent` and stop there. The canonical `Event` has no capacity field, so `dedupe.py` cannot express the documented "Maker Nexus wins capacity" preference — declaring it today would be validated and rejected, which is the intended loudness. When the field is added, add it to `MERGEABLE_FIELDS` and to the preference at the same time.
- **`conditional` defaults to off in `fetch_json`.** A 304 leaves no headers to read `X-WP-TotalPages` or `X-WP-Total` from, which would take both the pagination and the amputation guard out at once. The nightly run reaches the adapter through `process_source`, where a 304 is reported as `NOT_MODIFIED` and answered by carry-forward.
