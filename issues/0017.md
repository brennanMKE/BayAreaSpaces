## Description

Per-run diagnostics written every run, whether or not publication proceeded. This is the file the repair workflow reads.

## Expected behavior

`out/health.json` with, per source: HTTP status, content type, bytes, raw record count, post-expansion horizon count, previous-night count, latency, gate verdict, whether events were carried forward and how stale they are, and `LAST-MODIFIED` age where the source exposes it.

Plus run-level: total events, per-space totals, gate outcomes, whether the LLM stages ran, and start/end timestamps.

## Notes

The key downstream consumer: when a source shows 0 for three consecutive nights, that adapter has drifted and the OpenCode repair pass gets dispatched against that one space — with `raw/` from those nights as the diff material.

Make it easy to answer "did the source change or did we?" in ten seconds. That question is the whole reason `raw/` is retained.

Keep it stable and machine-readable; the website project may eventually surface a status page from it.
