## Description

`sources.yaml` needs a typed loader. It is the only place adapters are named, so the loader is also where the registry's shape gets validated — a typo in an adapter name or a filter key must fail at startup, not silently do nothing at 3 AM.

## Expected behavior

- Pydantic models for `defaults`, `spaces[]`, `sources[]`, `filters`, `health`, `spaceapi`.
- `${MAKER_CALENDAR_CONTACT}` expanded from the environment. **The loader must raise if it is unset, empty, or still contains `example.com`.** A run with no real contact is a bug, not a degraded mode — see `CLAUDE.md`.
- Unknown adapter names, unknown filter keys and unknown health keys are errors, not warnings.
- `enabled: false` sources are loaded but excluded from the run, and reported as skipped.
- Per-space `rate_limit_seconds` overrides the default (Ace needs 10).
- `sources: []` is valid (Lower 48 has no sources).

## Actual behavior

No loader.

## Notes

Adapter names currently in use: `ics`, `gcal_ics`, `tribe_rest`, `jsonld`, `nextdata`, `embedded_json`, `json`, `rss`, `bookwhen_html`, `llm_html`.

Filter keys: `location_contains`, `title_contains`, `location_excludes`, `title_excludes`, `categories_exclude`, `location_allow_when_missing`.

Health keys: `allow_zero`, `ignore_count_drop`, `require_nonzero_once`, `max_stale_days`.

Also present: `address_override`, `script_id` (for `embedded_json`), `params`, `calendar_id`, `label`, `trust`, `verified`, `notes`.

A test that loads the real `sources.yaml` and asserts 11 spaces / 30 sources / 25 verified is cheap and catches accidental registry damage.

## Root cause

`pipeline/config.py` was a docstring-only stub from issue 0004. Nothing read `sources.yaml` except `tests/test_registry.py`, which uses raw PyYAML and asserts on dicts, so the registry had no typed shape at all: any downstream stage would have been reaching into untyped dictionaries with `.get()`, and every one of the failure modes this project cares about — a misspelled adapter, a misspelled filter key, a missing contact — would have surfaced as an empty result rather than an error.

## Fix

`pipeline/config.py` now defines the registry as Pydantic models and exposes `load_registry(path, *, env=None) -> Registry`.

- **Models.** `Defaults`, `Space`, `Source`, `Filters`, `Health`, `SpaceApi`, `Registry`. Every one sets `extra="forbid"`, and `adapter` is a `Literal` over the ten implemented adapters (`KNOWN_ADAPTERS` is derived from it, so the type and the set can never disagree). An unknown adapter name, filter key, health key, source key or space key is a startup error. `Filters` and `Health` matter most here: filters drop events silently, so a misspelled key would quietly reshape a space's calendar with nothing in the log.
- **Contact.** `resolve_contact()` reads `$MAKER_CALENDAR_CONTACT` and raises `ContactError` when it is unset, empty, whitespace-only, contains `example.com` (case-insensitive), is not an `http(s)` URL, or contains whitespace or `)` that would corrupt the User-Agent comment field. There is deliberately no fallback value. It runs *before* the YAML is read so the error is unambiguous.
- **Placeholder expansion.** `${NAME}` tokens are expanded recursively over the raw data before validation, and an unrecognized name raises `RegistryError` rather than being left literal — otherwise a typo like `${MAKER_CALENDER_CONTACT}` ships verbatim in the User-Agent of every request.
- **Run set.** `space.enabled_sources` / `space.skipped_sources` (and `registry.enabled_sources` / `registry.skipped_sources`, which return `SourceRef(space, source)` pairs) keep `enabled: false` sources loaded and reportable while excluding them from the run. `registry.iter_enabled()` is the iteration order the nightly run should use.
- **Rate limits.** `space.effective_rate_limit_seconds` returns the per-space override when set and `defaults.rate_limit_seconds` otherwise. `Registry`'s after-validator attaches `defaults` to each space, so this needs no argument at the call site.
- **`TODO` url.** `Source.is_todo` detects the sequoia-fabrica / bookwhen-public placeholder (issue 0002). It loads, so the registry keeps documenting it; the fetch layer must skip it rather than requesting the literal string.
- **Target invariants.** `gcal_ics` must carry `calendar_id` and must not carry `url`; every other adapter is the reverse; `embedded_json` must carry `script_id`. `Source.target` returns whichever applies. Space ids must be unique, and source labels must be unique within a space.
- **Errors.** One base class, `ConfigError`, with `ContactError` and `RegistryError` beneath it. Pydantic's `ValidationError` is wrapped (and chained) so a caller has a single exception type to catch at startup.

## Gotchas

- **Nothing loads `.env` yet.** `resolve_contact()` reads the process environment only. On the mini this matters twice over: launchd does not read the shell profile, so the nightly job must either load `.env` explicitly or carry `MAKER_CALENDAR_CONTACT` in the plist's `EnvironmentVariables`. The error message says so, but the loading itself belongs to the CLI entry point (issue 0012) or the launchd job (issue 0031). `python-dotenv` is not a pinned dependency and was not added.
- **The contact check runs before the YAML is read**, so a missing contact raises even for a registry that never references the placeholder. That is intentional — a run with no real contact is a bug regardless of what the file says — but it means any tool that wants to lint `sources.yaml` still needs the variable set.
- **`load_registry(env=...)` exists for the tests.** It defaults to `os.environ`; production callers should not pass it.
- **`Space.effective_rate_limit_seconds` raises `ConfigError` on a hand-constructed `Space`.** Defaults are attached by `Registry`'s after-validator, so a `Space()` built directly in a test has none. That is a loud failure rather than a silent fallback to 2 seconds, which would be the wrong number for Ace.
- **`extra="forbid"` makes the registry a two-file change.** Adding a new key to `sources.yaml` — even a harmless documentation one — now fails the load until the corresponding model gains the field. That is the intent, and it is the same tripwire property as the hard-coded counts in `tests/test_registry.py`.
- `Filters` and `Health` default to all-false objects rather than `None`, so downstream code can write `source.filters.location_allow_when_missing` without a null check. `Filters.is_empty` distinguishes "no filters configured" when that matters for reporting.
