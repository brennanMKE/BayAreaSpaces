## Description

The only component that talks to a model. Called directly from Python over the OpenAI-compatible API at `http://localhost:1234/v1` — **not** through OpenCode, which stays out of the nightly path.

## Expected behavior

- `chat.completions.create` with `temperature=0` and `response_format={"type": "json_schema", ..., "strict": True}`.
- **Validate every response against a Pydantic model.** On failure, retry once with the validation error appended. On second failure, quarantine and log. **Never emit unvalidated model output.**
- Health-check `GET /v1/models` before the enrich stage. If it fails, skip the model stages and emit Tier A/B rather than failing the run.
- Small instruct model (3B–8B) by default; escalate to a larger model only for quarantined pages.
- Anchor every prompt with today's date explicitly.

## Notes

**The single most important constraint:** the model returns dates and times as **source-verbatim strings**, never computed ISO timestamps. `dateutil` plus the known source timezone does the parsing. A 27B model will confidently turn "Wednesday at 7pm" into a timestamp that is off by seven hours and never flag it.

Make sure only one LM Studio instance owns port 1234.

Scope note: the model does exactly two jobs (this issue enables 0028 and 0029). Of 25 verified sources, **24 parse deterministically** — every new `llm_html` entry should be treated as a small failure to find the real feed. Humanmade is the cautionary case: it looked like a scraping problem until an agent chased a Linktree to an unlinked Luma calendar.
