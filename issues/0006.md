## Description

The HTTP layer every adapter sits on. These are volunteer nonprofits on shared hosting, and this layer is where the project's good-citizen commitments are actually enforced rather than merely documented.

## Expected behavior

- One `httpx` client, HTTP/2, follows redirects, 30s timeout, 2 retries with backoff.
- **2 seconds between requests to the same host**, honoring per-space `rate_limit_seconds` (Ace's `robots.txt` sets `Crawl-delay: 10`).
- `robots.txt` honored per host via `urllib.robotparser`, cached per run. Path-level disallows bind regardless of which group we match.
- Honest User-Agent from the registry. **Never** impersonate a browser or another crawler — see the robots.txt section in `CLAUDE.md`.
- Conditional GET: `ETag` / `Last-Modified` stored per source; a 304 skips parsing and just bumps `last_seen`.
- Every response body written verbatim to `raw/YYYY-MM-DD/{space_id}-{label}.{ext}` before parsing. Never mutate `raw/`.
- On failure after retries: mark the source `failed` and **carry forward the previous run's events**. A transient 503 must never silently delete a space.

## Actual behavior

No fetch layer.

## Notes

**Return status, content type, body and byte count separately.** Do not collapse them into a success boolean. The survey found, live: 200 with `text/html` for `?format=ical`; 200 with a byte-identical homepage for `?ical=1`; 200 with an unfiltered full list from a supposed category feed; 404 with a valid populated RSS body; and 404 carrying `Content-Type: application/rss+xml` over a 1.35 MB HTML body. Adapters need all four facts to decide, and the layer must not pre-judge.

Two sources are large — Sudo Room's export is 8 MB and Maker Nexus's ICS is 11 MB. Conditional GET matters here, and `raw/` retention is capped at 30 days for a reason.

## Root cause

`pipeline/fetch.py` was a docstring-only stub from issue 0004. Every good-citizen commitment in `CLAUDE.md` — 2 seconds per host, `robots.txt` honored, an honest User-Agent, no crawling, conditional GET so steady state is mostly 304s — existed only as prose. This issue is where those become executable, and where the adapters (0007, 0008, 0019–0025) get the object they all consume.

## Fix

`pipeline/fetch.py` now exposes a `Fetcher` built once per run, plus the pure helpers it is assembled from.

- **`FetchResult` reports four facts separately.** `status_code`, `content_type`, `body` and `byte_count` are independent fields and are never collapsed into a success boolean. `outcome` is a **transport** verdict (`fetched` / `not_modified` / `blocked` / `skipped` / `failed`) and says nothing about whether the payload is the feed we wanted: a 404 carrying a valid RSS body comes back as `FETCHED` with `status_code == 404` and the body intact, because only the RSS adapter can decide that. Also carried: `charset`, `content_type_header` (verbatim, parameters and all), `headers`, `final_url`, `redirected`, `etag`, `last_modified`, `conditional`, `attempts`, `elapsed_seconds`, `rate_limit_delay_seconds`, `raw_path`, `reason`, `error`, plus `text`, `content_hash` and `source_key`.
- **The assertion is offered, not applied.** `result.expect_content_type("text/calendar")` raises `ContentTypeMismatch`; `result.content_type_is(...)` returns a bool. Both understand `text/*` wildcards and structured suffixes (`application/rss+xml` satisfies `application/xml`). The fetch layer itself never raises on a content type — the adapter makes the call.
- **Per-host rate limiting.** `RateLimiter` is keyed on the bare hostname (`host_of()`, port and scheme dropped), not on the space, so the four spaces publishing through `api.lu.ma` queue behind each other. The delay is `max(space.effective_rate_limit_seconds, robots Crawl-delay)` — Ace's 10 stands, and a host advertising a *smaller* `Crawl-delay` never lowers the registry's number. `sleep` and `clock` are injectable, which is what makes the timing testable without spending it.
- **`robots.txt` per origin, cached for the run.** `RobotsCache` fetches `{origin}/robots.txt` through the same rate limiter and parses it with `urllib.robotparser`. `RobotsRules.allows()` checks **both** our product token and the `*` group, which is deliberately stricter than RFC 9309's one-group rule and is how "path-level disallows bind us regardless of which group we match" is enforced. 404 → everything allowed. 5xx or a transport error → assume disallow (RFC 9309 §2.3.1.4) but report the source `failed` rather than `blocked`, so issue 0014 carries the space forward instead of dropping it. An explicit disallow is `blocked`, which must **never** be carried forward: we are not permitted to have that data.
- **Honest User-Agent, enforced at construction.** `assert_honest_user_agent()` refuses any UA containing a browser or crawler token (`mozilla`, `chrome`, `googlebot`, `claudebot`, `gptbot`, `curl/`, `python-httpx`, …) or lacking a contact URL. `Fetcher.__init__` calls it, so a dishonest UA stops the run before a socket opens.
- **Conditional GET behind a Protocol.** `HttpStateStore` is a `runtime_checkable` Protocol with `get(key)` / `put(key, state)` over a `SourceState` dataclass whose field names are issue 0013's intended columns (`etag`, `last_modified`, `last_status`, `last_success_at`, `last_seen`, `consecutive_failures`, `last_content_hash`). `InMemoryStateStore` is the default until 0013 lands SQLite; swapping it changes nothing in `fetch.py`. A 304 returns `body=None`, `byte_count=0`, keeps the stored validator and hash, and bumps `last_seen`/`last_success_at`.
- **`raw/` is write-once.** `archive_raw()` writes the body verbatim to `raw/YYYY-MM-DD/{space_id}-{label}.{ext}` *before* returning, including for 404s and wrong-content-type responses — those are the ones worth having on disk tomorrow. The extension is derived from what the server **said it sent**, not from the adapter, so a `boxshop-ical.html` sitting next to an `ics` adapter is the bug, visible in a directory listing. Re-archiving identical bytes reuses the existing file; differing bytes on the same day write a timestamped sibling rather than an overwrite.
- **Retries.** 30 s timeout, two retries after the first attempt, backoff `1 s` then `2 s`. `RETRY_STATUS_CODES` covers 408/425/429/5xx and the Cloudflare 52x range (525 is what `events.hackerdojo.com` has answered for over a year). **404 is deliberately not retryable** — one endpoint here answers 404 with a real feed. A response that is still a server error after retries is `FAILED` but keeps its status, content type and body.
- **URLs come from the registry, never from a guess.** `resolve_url()` builds the one templated URL in the system (`gcal_ics` → Google's fixed `public/basic.ics` path from `calendar_id`); `request_url()` merges `source.params`, which is load-bearing rather than cosmetic — The Crucible's Store API returns 200 and valid JSON with 72% of the catalog missing when `orderby=date` is absent. `TODO` urls and `enabled: false` sources return `SKIPPED` with no request. `fetch_url()` lets a paginating adapter walk `next_rest_url` inside the same limiter and the same robots decision.

## Gotchas

- **`robots.txt` costs a request, and that request is rate limited too.** The first fetch to a new host therefore sleeps one full delay between `robots.txt` and the feed. That is intentional politeness, but it means a run's floor is `2 × delay` per host rather than one, and Ace pays 20 s before its first byte.
- **Backoff and rate limiting compose rather than stack.** Time spent in backoff counts toward the per-host gap, so a 1 s backoff followed by a 2 s limit sleeps 1 s more, not 3 s. `test_retry_then_fail_marks_the_source_failed` pins the exact sequence, so changing either knob will fail loudly rather than quietly doubling how hard we hit a volunteer's shared host.
- **`outcome` is not a parse verdict and must not be read as one.** `FETCHED` means an HTTP answer arrived, nothing more. An adapter that treats `outcome is FETCHED` as "this is my feed" reintroduces exactly the bug `CLAUDE.md` warns about — Humanmade's Eventbrite page returning empty forever without erroring.
- **A `blocked` result must never be carried forward** (issue 0014). `failed` means we could not get the data; `blocked` means we are not permitted to have it, and republishing yesterday's copy would be working around the file rather than honoring it. An unreachable `robots.txt` is reported as `failed` precisely so a flaky host does not silently drop a space.
- **Conditional GET is inert until issue 0013.** `InMemoryStateStore` forgets everything on process exit, so every nightly run currently re-downloads Sudo Room's 8 MB and Maker Nexus's 11 MB in full. The interface is final; only the implementation is missing.
- **`raw/` retention is not implemented here.** The 30-day cap is still unowned — nothing prunes `raw/`, and at ~20 MB/night from two sources alone that matters within weeks.
- **`fetch_url()` is for pagination only.** It exists so `tribe_rest` can walk `next_rest_url` under the same limiter and robots decision. It is not a general fetcher, and "fetch only the URLs in `sources.yaml`" still binds: the caller must derive the URL from a registered source's own response.
- **The extension in `raw/` can disagree with the adapter, on purpose.** `boxshop-ical.html` means `?format=ical` served HTML. Do not "fix" the naming to follow the adapter; that disagreement is the diagnostic.
