## Description

Parse `schema.org/Event` from embedded `<script type="application/ld+json">`. Consumers: Ace's calendar page (12 events, third-line fallback) and The Box Shop's per-event pages.

## Expected behavior

- Collect **every** ld+json block, not just the first.
- Walk for `@type: Event`, handling `@graph`, bare arrays, and `ItemList`/`ListItem` wrappers. `extruct` handles these; hand-rolling will miss cases.
- Parse `startDate`/`endDate` with offsets intact (`-0700`).
- Where `location` is empty, fall back to the space's `address_override`.

## Notes

**The Box Shop needs a two-step flow**, which is why this adapter must accept a seed list rather than assuming one page: fetch `/events?format=rss` to enumerate item `<link>` URLs (the RSS itself carries no event date, only `pubDate`), then GET each `/events/<slug>` and parse its JSON-LD. Confirmed on one event resolving to `2026-08-08T18:00:00-0700`.

Respect robots: The Box Shop disallows `?format=json` and `?format=ical` for everyone; `?format=rss` is allowed and sufficient.

**Where JSON-LD looks available but is not:** The Crucible's product pages carry `schema.org/Course` with no `startDate`, no `offers` and no `hasCourseInstance` — a `jsonld` source there would return empty forever without erroring. Eventbrite organizer pages no longer emit JSON-LD at all (see 0023).

## Root cause

Not a bug — an unimplemented adapter. `jsonld` was one of the seven names in `sources.yaml` that the dispatch table skipped with an issue number, so Ace's `calendar-jsonld` and The Box Shop's `squarespace-events` were registered, verified and unreachable.

The design problem underneath it is that the two consumers are not the same shape. Ace's `/calendar/` is one page holding an array of `Event`. The Box Shop's registered URL is an **RSS index that contains no event dates at all** — `pubDate` is the post date (2026-06-29 for an event on 2026-08-08), so anything that read a date out of the feed would publish a calendar of announcement dates and nothing downstream would ever say so. That is why the adapter takes a seed list rather than assuming a single document.

## Fix

`pipeline/adapters/jsonld.py`, following `tribe_rest`'s conventions: a frozen `JsonLdParse` subclassing `IcsParse`, a `JsonLdEvent` subclassing `IcsEvent` so `normalize.from_ics_event` consumes it unchanged, a `JsonLdProblem` enum, a `parse` alias for the registry, and no raising for a bad payload.

- **Every block, and one bad block does not cost the rest.** Blocks are enumerated with `extruct`'s own XPath and decoded one at a time through `JsonLdExtractor`, because `extruct.extract()` **raises** on a malformed block and loses the whole document with it. `bad_blocks` is counted and reported.
- **Shapes.** `extruct` flattens a bare top-level array; it does *not* flatten `@graph` or `ItemList`/`ListItem`, so `iter_events` walks those (and `item`, `mainEntity`, `hasCourseInstance`, `subEvent`). The walk stops at an event, so an `Event` nested under another event's `location` is not counted twice. `@type` may be a list and any `*Event` subtype counts, plus `Festival`/`Hackathon`/`CourseInstance` by name.
- **Offsets intact.** `2026-08-08T18:00:00-0700` keeps `utcoffset() == -7h` and stays that instant; `-07:00` parses identically. A bare `2026-08-12` stays a `date`.
- **Two-step flow.** A body that sniffs as RSS/Atom is a seed list: item `<link>`s are read, capped at `MAX_SEED_FETCHES = 20`, and each is fetched through `Fetcher.fetch_url` via the `AdapterEntry.paginates` seam — one robots decision, one rate limiter, one `raw/` archive. A link with a robots-disallowed `?format=` or an off-host host is skipped *before a request is constructed*. A 404 on one seed costs one event and is reported; every seed failing is `SEED_FETCH_FAILED` so carry-forward runs.
- **Zero is never one thing.** `NO_JSONLD` (no block at all — Eventbrite's organizer pages, naming issue 0023), `NO_EVENTS` (blocks present, no `Event` — The Crucible's undated `Course`, naming what it found instead), and a seed feed with no items, which is `ok` with zero because The Box Shop is legitimately empty most of the year.
- **`location` is left alone, including empty.** Contrary to the issue text above, the adapter does **not** apply `address_override`: `normalize.VenuePolicy` (issue 0009) owns it and applies a deliberate majority rule that keeps a genuinely off-site event's own address. The adapter filling it in would erase the evidence that rule runs on.
- `pipeline/cli.py`: `jsonld` resolves to `parse_jsonld` with `paginates=True`, and `AdapterEntry.paginates` now documents both users of the seam.

## Gotchas

- **`extruct` raises rather than skipping.** One malformed ld+json block makes `extruct.extract()` throw `JSONDecodeError` and return nothing for the entire document. This is the single most surprising thing in the issue and the reason blocks are decoded individually.
- **`extruct` flattens arrays but not `@graph` or `ItemList`.** Half the work is still a manual walk. "extruct handles these" is true for the JSON quirks, not for the graph shapes.
- **A numeric offset is not a timezone.** `Event.tz` must be a resolvable IANA name: `normalize.day_start_utc` and issue 0016's health filter both call `ZoneInfo` on it, and `ZoneInfo("UTC-07:00")` raises — inside `evaluate_health`, which runs *outside* `process_source`'s per-source try/except, so it would take down the whole run rather than one source. Timed events therefore carry `DEFAULT_ZONE` as the rendering name while the value keeps the source's own offset, with `source_offset` and `zone_matches_offset` as the record.
- **Script bodies are raw text in HTML**, so entities are not decoded by the parser and `&amp;` arrives inside the JSON string. Every text field goes through `html.unescape`, as in `tribe_rest`.
- **`offers.price` is source text.** A `$` is prefixed only when the value is a bare number — the first draft turned `"sliding scale $10-30"` into `"$sliding scale $10-30"`, which is the same class of damage as parsing it to a float, in miniature.
- **The Box Shop has no `address_override` in the registry today**, deliberately: they are mid-move and the recorded decision is not to publish a hardcoded address. Its JSON-LD events therefore publish with no address at all until that is settled, which is correct and is worth knowing before someone reads it as a bug.
