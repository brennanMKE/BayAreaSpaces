# 0032 — Health alerting

| | |
|---|---|
| **Status** | open |
| **Module** | health |
| **Platform** | macOS |
| **First seen** | 2026-08-05 |

## Description

Surface gate failures and drifted sources without requiring someone to read `health.json` every morning.

## Expected behavior

- `terminal-notifier` on gate failure, plus an appended `ALERTS.md`.
- Optional ntfy.sh for phone delivery.
- Alert on: any gate blocking publication, a source failing 3 consecutive nights (the repair trigger), and a source exceeding `max_stale_days`.
- **Do not alert on the four benign zero cases** — `allow_zero`, `ignore_count_drop`, `require_nonzero_once` and a short publishing horizon all produce zeros or drops that are correct. An alerting system that cries wolf monthly gets ignored, which is worse than no alerting.

## Notes

The Box Shop alone would fire roughly monthly without `allow_zero`, at ~8–12 events a year.

Pair with the OpenCode repair workflow in `CLAUDE.md`: three consecutive zero nights means an adapter has drifted, and the alert should name the space and the `raw/` paths to diff.
