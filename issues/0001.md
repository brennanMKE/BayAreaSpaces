# 0001 — Bot about page does not exist, so the User-Agent contact points nowhere

| | |
|---|---|
| **Status** | open |
| **Module** | docs / fetch |
| **Platform** | All |
| **First seen** | 2026-08-05 |

## Description

`sources.yaml` builds its User-Agent from `${MAKER_CALENDAR_CONTACT}`, which is set to an about-page URL on `brennan.sstools.co`. That page does not exist yet. **Nothing may be fetched until it resolves** — a User-Agent pointing at a 404 is worse than no contact at all, because it looks like a bot performing accountability, and the whole robots.txt position in `CLAUDE.md` rests on being genuinely reachable.

## Expected behavior

The URL in `$MAKER_CALENDAR_CONTACT` returns 200 and describes: what this bot is, which sources it fetches and how often, and how to ask us to stop. Opt-outs are honored immediately and without argument.

## Actual behavior

No page. `.env` has not been created from `.env.example` either, so the loader would fail (correctly) on an unset variable.

## Notes

The page satisfies a requirement the project already had — the good-citizen section of the handoff calls for an about page listing every source, the refresh cadence, and a one-email opt-out. One page, two jobs.

Deliberately uses a URL rather than an email so no address appears in git, in a request header, or in any makerspace's access logs.

Steps: publish the page, then `cp .env.example .env` and set `MAKER_CALENDAR_CONTACT` to its real URL. Note that launchd does not read the shell profile, so the nightly job must load `.env` explicitly or carry the value in the plist's `EnvironmentVariables`.
