# 0025 — RSS adapter

| | |
|---|---|
| **Status** | open |
| **Module** | adapters |
| **Platform** | macOS |
| **First seen** | 2026-08-05 |

## Description

Parse RSS/Atom. The critical constraint: **most RSS feeds are not event sources**, because their `pubDate` is when the post was published, not when the event happens.

## Expected behavior

- Parse RSS 2.0 and Atom.
- **Require an explicit per-source declaration of whether `pubDate` is the event start.** Do not guess. Default to treating the feed as change-detection only.
- When a feed is change-detection only, emit no events — surface a liveness signal for `health.json` instead.
- Support two-step use: enumerate item `<link>` URLs as a seed list for another adapter (The Box Shop, The Crucible).

## Notes

Per-source truth established 2026-08-05:

| Feed | `pubDate` means | Usable as events? |
|---|---|---|
| Sudo Room `/events/feed/` | **event start** | Yes — the one genuine case |
| Meetup `/events/rss/` (all spaces) | post date | No — enumerated every tag to confirm |
| The Box Shop `/events?format=rss` | post date | Seed list only |
| The Crucible `/category/upcoming-events/feed/` | post date | Seed list only; dates live in title text like `(JUL 16)` |
| Mastodon `.rss` | post date | Announcement signal only |

Mastodon and Bluesky feeds are registered at `trust: 10` as change signals. Both of Sequoia Fabrica's are stale (last posts 2025-12-23 and 2025-07-08); Instagram is their live channel and has no feed.

**Two traps:** Ace's `/calendar/feed/` returns **404 with a populated 9.8 KB RSS body** — a body-trusting parser ingests it, a status-checking parser drops it. The Crucible returns **404 with `Content-Type: application/rss+xml` over a 1.35 MB HTML body** — there the header lies. Check status, content type and parse result, and treat disagreement as failure.
