# 0021 — embedded_json adapter (new)

| | |
|---|---|
| **Status** | open |
| **Module** | adapters |
| **Platform** | macOS |
| **First seen** | 2026-08-05 |

## Description

New adapter: parse a **named** `<script type="application/json" id="…">` blob out of a server-rendered page and map its bespoke shape. Not covered by anything existing — `jsonld` is schema.org-specific, `nextdata` is hardcoded to `__NEXT_DATA__`, and `json` expects a standalone document at a URL.

Consumer: The Crucible, the largest clean catalog in the registry.

## Expected behavior

- Configurable `script_id` (The Crucible uses `ac-course-data`) plus a field map.
- Decode `start_dates[]` as **Unix epoch seconds, local America/Los_Angeles**. Verified against the product page's `Class.Date` attribute to the minute.
- UID `{id}:{start_epoch}`.
- Skip the 9 courses with an empty `start_dates` array.
- **Each `start_date` is one RUN of a course, not one meeting.** A 5-week 20-hour course is one entry — which is what a merged calendar wants.
- **Do not compute `DTEND` from `hours`** — that field is total course hours, not session length, so it would render 40-hour blocks.
- Unescape HTML entities before matching filters: the blob stores `Glass Fusing &amp; Slumping`.

## Notes

Verified 2026-08-05: 132 KB blob, 216 courses, 478 offerings, **271 inside 120 days**. Cross-validates against the WooCommerce API's 274 (issue 0022).

There is **no XHR endpoint and no server-side filtering** — `?department=` and a bogus `?department=ZZZ` return the identical 216-course blob. All filtering in their UI is client-side.

`/shop/` carries a byte-identical blob; do not ingest both.

`nextdata` could later be reimplemented on top of this adapter — it is this with `script_id` fixed.
